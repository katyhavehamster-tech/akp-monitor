# Словник даних — Завдання 2

Синтетичний набір даних за структурою антикорупційної програми. Стан на 10.11.2026, версія 0.1. Усі значення вигадані.

Звітний період набору — І півріччя 2026 року (01.01–30.06.2026). Дата зрізу даних — 06.07.2026: на цей день координатор готує звіт для Порталу доброчесності.

Формати: CSV (UTF-8, кома, перший рядок — назви полів), `nabir.xlsx` (аркуш на таблицю), `nabir.json` (`{"meta": …, "tablytsi": {назва: [рядки]}}`). Дати — ISO `РРРР-ММ-ДД`, дата і час — `РРРР-ММ-ДДTГГ:ХХ`. Порожнє значення — порожній рядок.

## Правила формування звіту

1. **Розділи.** Звіт містить усі заходи всіх трьох розділів.
2. **Стан виконання.**
   - Строк — конкретна дата після 30.06.2026, і захід не виконано → «Строк виконання заходу не настав».
   - `vykonano` → «Виконано»; `chastkovo` → «Частково виконано».
   - Інакше (`ne_vykonano`, `v_roboti`, `ne_rozpochato` за строку, що минув) → «Не виконано».
3. **Фактичний строк виконання.**
   - Постійний або періодичний захід → кінцева дата півріччя, 30.06.2026 (так вимагає Розʼяснення № 3).
   - Виконаний захід з датою → `fakt_data`.
   - Інакше поле порожнє. Розʼяснення не каже, яку дату вказувати для невиконаного заходу чи заходу, строк якого не настав, а Портал вимагає заповнити поле. Це відкрите питання, див. README.
4. **Опис результату.** Для «Строк виконання заходу не настав» не заповнюється. Для «Не виконано» має містити пояснення причин. Опис має містити вимірюваний результат, який відповідає індикатору, і за наявності — посилання на відкрите джерело. Опис, що лише повторює зміст заходу, НАЗК вважає неприпустимим.

## Сигнали Risk Flags — приклад явних правил

Правила організаторів, за якими побудовано навмисні кейси. Команда може запропонувати інші, але кожен сигнал має давати явне правило, яке можна показати користувачу (п. 4 Політики використання ШІ).

| Код | Правило | Обʼєкт |
|---|---|---|
| RF1 | строк — дата ≤ 30.06.2026, статус не `vykonano` | захід |
| RF2 | статус `vykonano` або `chastkovo`, підтвердних матеріалів 0 | захід |
| RF3 | захід R2 зі статусом `vykonano`, а індикатор його ризику пройшов менше 10 % шляху від базового до цільового значення | захід |
| RF4 | статус `vykonano` або `chastkovo`; в описі немає цифр і посилань; подібність до змісту ≥ 0,6 (коефіцієнт Жаккара на множинах перших пʼяти літер слів довжиною від 4 літер) | захід |
| RF5 | статус `vykonano` або `chastkovo`, строк настав (або захід постійний), `indykator_fakt` < `indykator_tsil` | захід |
| RF6 | строк заходу переносили ≥ 2 разів, або в підрозділі ≥ 2 прострочені заходи | захід, підрозділ |
| RF7a | `fakt_data` пізніше за 30.06.2026 | захід |
| RF7b | захід із датою, і всі його підтвердні документи датовано пізніше за `fakt_data` | захід |
| RF7c | стан на Порталі «Не виконано», а опис порожній | захід |
| RF7d | ризик високого чи критичного рівня без жодного заходу | ризик |
| RF7e | стан «Строк виконання заходу не настав», а опис заповнено | захід |

Кожен навмисний кейс і правило, що його ловить, — у `kliuch/ochikuvani-sygnaly.csv` (29 сигналів). Генератор перевіряє, що правила дають рівно ці сигнали, не більше й не менше.

Що навмисно закладено:

- прострочені заходи — 6, з них два в одному підрозділі (P10);
- виконані заходи без підтвердження — 4;
- формальне закриття (захід виконано, ризик не змінився) — 5 заходів трьох ризиків;
- опис, що повторює зміст заходу, — 4;
- показник нижче цілі — 3, зокрема один зі статусом «виконано»;
- строк переносили двічі — 1;
- дата виконання поза звітним періодом, підтвердження «заднім числом», невиконаний захід без пояснення, ризик без заходів, опис для заходу з майбутнім строком — по 1.
