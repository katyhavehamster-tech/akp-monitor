# Архітектура та політика кібербезпеки «АКП-Монітор»

Цей документ описує реалізовану багаторівневу модель захисту інформації та архітектуру кібербезпеки цифрової системи моніторингу виконання антикорупційної програми («АКП-Монітор»), побудовану відповідно до вимог стандартів **OWASP Top 10**, нормативних засад захисту інформації з обмеженим доступом (ІзОД / ДСК) та принципів мінімізації привілеїв.

---

## 1. Криптографічний ланцюжок аудиту дій (`AuditLog` SHA-256)

Кожна операція в системі (вхід, створення або редагування заходу чи підрозділу, завантаження доказу, перенесення строків, погодження, формування звітності або друк) фіксується в незмінному журналі аудиту:

* **Математична незмінність ланцюжка:** кожен новий запис містить хеш попереднього запису (`prev_hash`). Значення поточного хешу формується за формулою:
  $$\text{hash} = \text{SHA-256}(\text{id} \parallel \text{timestamp} \parallel \text{actor\_code} \parallel \text{action} \parallel \text{obj\_type} \parallel \text{obj\_id} \parallel \text{field} \parallel \text{old} \parallel \text{new} \parallel \text{prev\_hash})$$
* **Усунення Race Condition (OWASP Concurrency Control):** запис у журнал обгорнуто в `transaction.atomic()` із блокуванням останнього запису на рівні СУБД через `AuditLog.objects.select_for_update().order_by('-id').first()`. Це виключає виникнення розгалужень ланцюжка при одночасних паралельних транзакціях (наприклад, масовий друк або експорт кількома користувачами).
* **Автоматична верифікація та відновлення:** доступний ендпоїнт перевірки цілісності `/api/audit/verify` та management-команда `python manage.py repair_audit_chain` для аудиту та автоматичного контролю ланцюжка без втручання в зміст зафіксованих подій.

## 2. Верифікація зліпків звітів та документів (`/verify` та QR-коди)

* **Цифрові відбитки (Digital Snapshots):** при генерації офіційних звітів за формою НАЗК або аналітичних довідок система формує детермінований цифровий зліпок вмісту (SHA-256).
* **Публічна перевірка автентичності (`/verify`):** будь-яка зацікавлена особа, уповноважений або орган контролю (НАЗК/МОУ) може перевірити автентичність наданого паперового чи електронного звіту за його контрольним хешем або кодом.
* **QR-коди на друкованих формах ДСТУ 4163:2020:** у колонтитули експортованих документів DOCX та PDF автоматично вбудовується QR-код і контрольна сума, сканування яких веде на захищену сторінку верифікації системи.

## 3. Захист інформації з обмеженим доступом (ІзОД / ДСК)

* **Відомчий контур:** система оптимізована для автономного функціонування в закритій відомчій мережі без передачі даних у зовнішні комерційні хмари.
* **Персоналізовані динамічні водяні знаки:** при завантаженні або перегляді матеріалів аналітиком (`ANAL`) чи користувачем з обмеженими правами на документи DOCX/XLSX автоматично накладається цифровий слід із зазначенням посадового коду користувача, ролі та точної часової мітки завантаження (захист від витоків та несанкціонованого фотографування екрана/роздруківки).
* **Ізоляція файлів підтверджень:** прямий доступ до директорії `/media/` заборонено на рівні вебсервера (`HTTP 403 Forbidden`). Віддача підтвердних файлів здійснюється виключно через авторизований ендпоїнт `/api/measures/<code_z>/evidence/<code_e>/file` з перевіркою належності користувача до підрозділу-виконавця або ролі Уповноваженого (`KOORD`) / Адміністратора (`ADMIN`).

## 4. Захист анонімних опитувань ($k$-анонімність)

* **Поріг $k$-анонімності ($k \ge 5$):** аналітичні зрізи та розподіл відповідей респондентів відображаються лише у випадку, якщо кількість відповідей у групі становить не менше 5 осіб (налаштовується через `SystemSettings.min_survey_group`). При меншій вибірці дані автоматично приховуються для запобігання деанонімізації співробітників.
* **Автоматична деперсоналізація (PII Masking):** парсер опитувань Google Форм (`surveys.py`) автоматично виявляє та маскує поштові адреси, ПІБ та контактні дані респондентів значенням `[приховано]`.
* **Нормалізація неінформативних відповідей:** алгоритмічне відсіювання відписок і шумів («-», «.», «не знаю», «відсутні») із забезпеченням чистоти вибірки.

---

## 5. Автентифікація, Rate Limiting та захист від перебору паролів

* **Захист від Brute-Force (Rate Limiting):** ендпоїнт `/api/auth/login` захищений лімітом запитів через розподілений кеш — не більше 10 невдалих спроб на хвилину з однієї IP-адреси або для одного логіна. При перевищенні повертається `HTTP 429 Too Many Requests`.
* **Захист від User Enumeration:** час відповіді та текст помилки при невірному паролі та неіснуючому обліковому записі є повністю ідентичними (`{"detail": "Невірний логін або пароль."}`), що унеможливлює перебір дійсних логінів.
* **Захист від Log Injection (CWE-117):** перед записом у журнал дій введене ім'я користувача очищується від символів переносу рядка (`\r`, `\n`) та невидимих керуючих символів (`\x00-\x1f`, `\x7f-\x9f`). Паролі та секретні токени ніколи не записуються в логи.
* **Кешування без ін'єкцій:** ключі кешу обмеження частоти запитів формуються за хешами SHA-256 (`login_fail:u:<hash>`, `login_fail:ip:<hash>`), запобігаючи Memcached/Redis Key Injection.

## 6. Захист від CSV/XLSX Formula Injection (OWASP CWE-1236)

* При експорті реєстрів заходів, звітів НАЗК та аналітики опитувань у формати `.csv` та `.xlsx` усі текстові значення перевіряються на наявність формульних префіксів:
  $$\text{Символи ризику: } =, +, -, @, \backslash t, \backslash r$$
* Якщо рядок починається з цих символів і не є чистим числовим значенням (наприклад, номером телефону `+380...` чи від'ємним числом `-12`), до клітинки автоматично додається одинарна лапка `'`, що нейтралізує інтерпретацію формул у Microsoft Excel та LibreOffice Calc.

---

## 7. Суворий білий список і сигнатурна валідація завантажень (Magic Bytes)

* **Білий список розширень:** дозволено завантаження виключно безпечних форматів документів і графіки: `.pdf`, `.docx`, `.xlsx`, `.png`, `.jpg`, `.jpeg`.
* **Явне блокування загроз:** файли з макросами (`.docm`, `.xlsm`, `.pptm`), скрипти та виконувані файли (`.exe`, `.sh`, `.js`, `.svg`, `.html`, `.bat`, `.cmd`, `.vbs`, `.ps1`, `.jar`) блокуються негайно (`HTTP 400`).
* **Сигнатурний аналіз (Magic Bytes):** перші байти вмісту звіряються з еталонними сигнатурами форматів (PDF: `%PDF`, PNG: `\x89PNG\r\n\x1a\n`, JPEG: `\xff\xd8\xff`).
* **Глибока інспекція OpenXML:** архіви `.docx` та `.xlsx` перевіряються на валідність структури ZIP, а їхній внутрішній каталог інспектується на відсутність виконуваного коду та компонентів макросів `vbaProject.bin`.
* **Жорсткий ліміт розміру файлу:** встановлено обмеження не більше 20 МБ на рівні вебсервера Caddy (`request_body max_size 20MB`) та бекенда Django (`MAX_EVIDENCE_BYTES = 20 * 1024 * 1024`), що захищає сервер від DoS-атак переповнення дискового простору.
* **Детектор дублювання документів:** автоматичне порівняння SHA-256 завантажуваних файлів запобігає прикріпленню одного й того самого документа до різних заходів.

## 8. Захисні заголовки безпеки (HTTP Security Headers)

Вебсервер Caddy та Django Middleware формують сучасний профіль безпеки:

| Заголовок | Значення / Призначення |
|---|---|
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains; preload` (примусовий HTTPS) |
| `Content-Security-Policy` | `default-src 'self'; script-src 'self'; object-src 'none'; frame-ancestors 'none'` |
| `X-Content-Type-Options` | `nosniff` (блокування MIME-sniffing) |
| `X-Frame-Options` | `DENY` (повний захист від Clickjacking) |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=(), payment=(), usb=()` |
| `Referrer-Policy` | `strict-origin-when-cross-origin` |
| `Content-Disposition` | `attachment; filename="safe_name.ext"` для всіх завантажуваних доказів |
| `Cache-Control` | `no-store, no-cache, must-revalidate, private` для чутливих API |
| **Приховання стеку** | Заголовки `Server`, `X-Powered-By` та `Via` повністю видаляються з відповідей |

## 9. Конфігурація продуктивного середовища (Production Hardening)

* **Вимкнений режим налагодження (`DEBUG = False`):** керується змінною середовища `DJANGO_DEBUG` і за замовчуванням завжди вимкнений (`False`).
* **Уніфікований JSON-обробник помилок:** при виникненні будь-яких неочікуваних винятків (HTTP 500/404/403/400) система повертає стандартизовану JSON-відповідь без витоку внутрішніх стектрейсів, шляхів файлової системи чи SQL-запитів.
* **Захист CSRF:** сувора перевірка токенів `csrftoken` із `SameSite=Lax` та перевіркою `CSRF_TRUSTED_ORIGINS`.
