# Карта і бачення інтеграції

> Назви конкретних відомчих систем і наявність у них API треба уточнити з менторами та ІТ-підрозділом
> органу. Нижче - логіка інтеграції, яку підтримує наша архітектура.

## Як АКП-Монітор вбудовується

1. **Як модуль наявної ІС.** Один контейнер з REST API (`/api/…`, специфікація OpenAPI на `/api/docs/`).
   Інтерфейс можна не використовувати: наявна система викликає API напряму.
2. **Як окремий сервіс у закритому контурі.** Docker + PostgreSQL, без зовнішніх хмарних залежностей.
3. **Автентифікація.** Зараз - токени. Для відомчого контуру замінюється на наявну систему єдиного входу
   (LDAP / Active Directory, OIDC) без змін у бізнес-логіці; роль і підрозділ беруться з довідника персоналу.

## Карта даних

| Джерело (тип системи) | Які дані отримувати | Навіщо в АКП-Монітор | Спосіб |
|---|---|---|---|
| Система електронного документообігу органу | реквізити наказів, протоколів, листів; файли | підтвердні матеріали без ручного завантаження, перевірка дати документа (RF7b) | API СЕД або імпорт реєстру документів |
| Кадрова ІС / довідник штату | структура підрозділів, посади (без ПІБ) | ролі й підрозділи користувачів, звʼязок «виконавець - підрозділ» | щоденна синхронізація довідника |
| Системи закупівель (наприклад, Prozorro та відомчі майданчики) | кількість процедур, скарги, частка неконкурентних закупівель | автоматичні значення індикаторів ризиків закупівель (KR01, KR13) | публічні API / вивантаження |
| Відкриті реєстри НАЗК (наприклад, реєстр осіб, що вчинили корупційні правопорушення) | факти збігів за перевірками | підтвердження заходів моніторингу реєстрів | відкриті дані НАЗК |
| Облік майна й оренди | договори оренди, спосіб укладення | індикатор KR09 «частка договорів через е-аукціони» | вивантаження |
| Система внутрішнього аудиту | результати перевірок | обʼєктивні дані для індикаторів ризику | вивантаження / API |

## Вихідні дані

| Куди | Що | Формат |
|---|---|---|
| Портал доброчесності НАЗК | звіт за півріччя: три розділи; «Фактичний строк виконання», «Стан виконання», «Опис результату або пояснення причин» | дані в структурі полів Порталу (XLSX/CSV, по аркушу на розділ); друкована форма для програм з обмеженим доступом |
| Департамент з питань запобігання та виявлення корупції МОУ | зведений стан програм підпорядкованих органів, стан ризиків, сигнали | REST API (`/api/dashboard`, `/api/risks`, `/api/flags`), XLSX |
| Керівництво органу | аналітична довідка з рекомендаціями | Markdown / друк у PDF |
| Моніторинг Державної антикорупційної програми | статус заходів, повʼязаних із ДАП | REST API, CSV |

## Бачення розвитку інтеграції з ІС МОУ та НАЗК

1. **Етап 1 (MVP, зараз):** експорт у структурі Порталу; уповноважена особа переносить дані без перероблення.
2. **Етап 2:** API-обмін з Порталом доброчесності, якщо НАЗК відкриє такий канал. Наш формат уже збігається з полями Порталу.
3. **Етап 3:** зведений рівень МОУ. Кожен орган має свій екземпляр або програму в спільному екземплярі;
   Департамент бачить агреговані панелі без доступу до чернеток підрозділів.
4. **Етап 4:** автоматичне наповнення індикаторів ризиків з первинних систем (закупівлі, майно, кадри),
   щоб оцінка зменшення ризику не залежала від самозвітування.
